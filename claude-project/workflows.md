# 워크플로우 — 흔한 상황별 분기

각 시나리오는 Claude가 자동으로 따라가는 의사결정 흐름입니다. 사용자는 자연어로 시작하면 됩니다.

## W1. 영수증/세금계산서 한 장 → 분개

**트리거**: 사용자가 이미지 첨부 + "이거 분개해줘" / "넣어줘" / "기장"

```
영수증 첨부 도착
  │
  ▼
Claude 비전이 다음 필드 추출 시도:
  • 거래처명(상호)
  • 거래일자
  • 공급가액 (부가세 별도)
  • 부가세액
  • 면세 표시 ("면세", "부가세 없음", 0원)
  • 매출/매입 (영수증 발행자 = 매입, 우리 매출 영수증 = 매출)
  │
  ▼
[분기 A] 어느 고객사인지 명시됐나?
  ├─ 예: 그대로 진행
  └─ 아니오 → list_clients 호출 → 사용자에게 선택지 제시
  │
  ▼
[분기 B] 결제 방법이 명시됐나?
  ├─ "외상", "어음", "매출금/매입금" → CREDIT
  └─ 그 외 → CASH (기본)
  │
  ▼
[분기 C] 필드 누락 있나?
  ├─ 있음 → 사용자에게 1문장 질문 ("부가세 별도 맞나요?", "거래일자 5/12 맞죠?")
  └─ 없음 → 다음으로
  │
  ▼
확인 카드 출력 (반드시):
  ┌────────────────────────┐
  │ 고객사: 샘플상사         │
  │ 거래일자: 2026-05-12   │
  │ 거래처: ABC상사        │
  │ 구분: 매출 / 현금       │
  │ 공급가액: 1,000,000원   │
  │ 부가세: 100,000원      │
  │ 합계: 1,100,000원      │
  │ → 진행할까요?           │
  └────────────────────────┘
  │
  ▼
사용자 응답
  ├─ "예/응/ok" → create_journal_entry 호출 → 결과 id 회신
  ├─ "수정 ..."  → 해당 필드 수정 후 확인 카드 다시
  └─ "아니/취소" → 중단
```

## W2. 자연어 분개 ("○○에 ××원 매출")

**트리거**: "샘플상사 5/12 ABC상사에 100만원 매출 현금"

```
파싱:
  clientName=샘플상사  occurredOn=2026-05-12  counterparty=ABC상사
  supplyAmount=1,000,000  direction=SALE  settlement=CASH
  │
  ▼
W1의 [분기 A부터] 동일하게 진행
  (단, 부가세는 "부가세 포함"이라고 명시되면 분리: 11,000원 입력 시 supply=10000 + vat=1000)
```

### 부가세 포함/별도 처리 규칙

| 사용자 표현 | 해석 |
| --- | --- |
| "100만원 매출", "공급가액 100만" | supplyAmount = 1,000,000 (부가세 별도 = +100,000) |
| "VAT 포함 110만", "합계 110만" | supplyAmount = 1,000,000, 부가세 100,000 |
| "면세 100만" | supplyAmount = 1,000,000, isTaxFree=true |

## W3. 영수증 여러 장 일괄 처리

**트리거**: 사용자가 여러 사진 첨부 + "다 분개해줘"

```
1. 모든 이미지에서 필드 추출 (순서대로 1, 2, 3...)
2. 표로 한꺼번에 제시:
     #  날짜       거래처     공급가액    부가세     구분
     1  5/12      ABC       1,000,000   100,000   매출
     2  5/13      DEF       500,000     50,000    매입
     3  5/14      GHI(면세) 300,000     -         매입
3. "위 3건 모두 저장할까요? (수정: 'N번 ...')"
4. 동의 → 한 건씩 create_journal_entry 반복 → 결과 요약
```

## W4. 부가세 신고 시즌 (1월/7월)

**트리거**: "부가세 신고 자료 줘", "1기 확정 준비"

```
[분기 A] 사업자 유형 + 기수 확인:
  • 법인 1기 확정 → 4~6월
  • 개인 일반 1기 → 1~6월
  • 법인 2기 확정 → 10~12월
  • 개인 일반 2기 → 7~12월
  • 간이과세 연 1회 → 1~12월
  │
  ▼
get_client_vat_aggregate(clientId, from, to) 호출
  │
  ▼
결과를 신고서 양식 표로 정리:
  ┌─────────────────────────────────────┐
  │ 1기 확정 (2026.01.01 ~ 06.30)        │
  ├─────────────────────────────────────┤
  │ 매출 공급가액   ........  ₩ ○○      │
  │ 매출세액      ........  ₩ ○○       │
  │ 매입 공급가액   ........  ₩ ○○      │
  │ 매입세액      ........  ₩ ○○       │
  │ ─────────────────────────────────── │
  │ 납부세액      ........  ₩ ○○       │
  └─────────────────────────────────────┘
  │
  ▼
"홈택스 전자신고는 본 시스템 외부에서 진행해야 합니다.
 본 자료를 참고해 직접 입력하거나, 세무 전문가에게 위임하세요."
```

## W5. 월말 마감 (매월 첫째 영업일)

**트리거**: "월말 마감", "이번 달 다 끝났나"

```
1. get_upcoming_checklist(clientId, days=30) → 다음 30일 마감 항목
2. list_recent_journal_entries(clientId, limit=20) → 이번 달 분개 누락 확인
3. 안내 출력:
   ✅ 이번 달 분개 N건 입력됨
   ⚠️ 다음 마감:
      • 6/10 원천징수이행상황신고 (D-9)
      • 6/10 4대보험료 납부 (D-9)
   📌 권장 작업:
      • 5월 급여 명세서 정리
      • 부가세대급금/예수금 계정 잔액 점검
```

## W6. "이런 거래 어떻게 분개해?" 상담

**트리거**: 도구 호출 없이 회계 질문

```
예: "차량 100만원에 샀으면 어떻게 분개해?"

→ knowledge/account-codes.md 참조해 설명:
  차변: 차량운반구 1,000,000원
  대변: 현금 1,000,000원 (또는 미지급금/장기차입금)

→ "이대로 저장해드릴까요?"
  - 단, 현재 시드 계정과목(7개) 안에 없으면 "수동 입력 필요" 안내
```

## W7. 회의 준비 (세무사 ↔ 고객사)

**트리거**: "다음 미팅 준비 자료 만들어줘"

```
1. list_clients → 어느 거래처
2. get_upcoming_checklist(60일)
3. get_client_vat_aggregate(현재 분기)
4. list_recent_journal_entries(30건)
5. 한 페이지 요약:
   • 다가오는 마감 5개
   • 분기 부가세 예상
   • 최근 30일 거래 동향 (매출/매입 합계)
```

## 일반 원칙

- **확인 없이 DB 쓰기 금지** — W1~W3 모두 확인 카드 단계 필수
- **추정 금지** — 모르면 1문장으로 묻기
- **금액 단위 일관성** — 항상 원, 천단위 구분
- **세율은 2025년 귀속 기준** — 사용자가 다른 연도 언급 시 안내
